# Практический комплект курса: редакция 2026-10-06.1

Реализованы первые три приоритета следующего улучшения курса: запускаемые лаборатории, подробные материалы сложных механизмов и набор работ для проверки качества ревью. Этот отчёт дополняет [предыдущие изменения программы](course-improvements-2026-10-06.md).

После освобождения места выполнен [реальный Linux/Docker/Kubernetes-прогон и исправлены найденные дефекты](course-toolkit-runtime-2026-10-06.md). Ниже сохранена первичная матрица; актуальные результаты находятся в продолжении отчёта.

Сохранены 30 обязательных тем, 92 части и 6 факультативов. Материалы подключены к существующим темам, предпосылки не переставлены. Подготовительный блок Java → Python, короткий вводный проект и контрольные Git-теги этапов не добавлены. Авторские проверки не изменяют зачёты ученика и не означают прохождение им курса.

## Что добавлено

### 11 лабораторий с намеренными неисправностями

[Инструкция и матрица сред](../backend-devops-theory/assets/labs/README.md), [запускатель](../backend-devops-theory/assets/labs/lab.py), [каталог заданий](../backend-devops-theory/assets/labs/catalog.py).

Для каждого случая доступны `prepare`, `check`, `reset` и авторский `reference`. Ученик получает исходники с дефектом, исправляет их, повторяет проверку и объясняет причину. Проверка сохраняет JSON с результатом, исходными хешами и наблюдениями. Коды завершения различают выполнение критериев, нарушение и непроверенную среду.

Рабочий каталог должен быть новым. Маркер принадлежности, блокировка одновременного запуска и отказ от symlink/hardlink защищают границы обычной работы. Reset перезаписывает только известные исходники задания; данные, доказательства и дополнительные файлы сохраняются. Это механизм организации упражнений, не sandbox для недоверенного кода.

Лаборатории не устанавливают инструменты, не скачивают образы и не создают облачные ресурсы. Docker использует локальный образ по digest; кластерные упражнения принимают явный контекст локального kind. Запас диска проверяется до запуска инфраструктуры. Kubernetes сохраняет PVC и namespace, останавливая свои deployments; явное удаление данных описано отдельно.

### 12 работ для проверки качества ревью

[Инструкция](../backend-devops-theory/assets/review-benchmark/README.md), [экспорт и оценка](../backend-devops-theory/assets/review-benchmark/benchmark.py).

Корпус включает четыре ошибки реализации, корректные альтернативы, дефект теста, ограничение среды, новое требование и недостаточное доказательство конкурентной корректности. Слепой экспорт выдаёт задание и работу без авторских ключей. Проверяющий возвращает классификацию, вердикт, состояние критериев и карточки замечаний.

Оценщик учитывает найденные и пропущенные ошибки, ложные обвинения, пропущенные/дублированные работы и структуру обратной связи. Он **не подтверждает истинность объяснения по совпавшей метке**: семантическая проверка человеком остаётся обязательной. Независимый слепой прогон модели в этой редакции не проводился; авторская самопроверка не названа независимой.

Автоматические проверки:

- **33 теста прошли**: лаборатории, примеры, корпус ревью, структура курса и локальные ссылки.
- Синтаксис 11 Python-файлов и 26 выдаваемых вариантов Python-исходников разобран успешно.
- Закрытие Markdown-блоков кода и `git diff --check` проверены.
- Хеши 671 существующего Markdown/JSON-файла в `learning/` и прежнем `course-audit/` совпали с исходными.
- Проверка Linux/Docker/Kubernetes через mock или рендеринг не засчитана как успешный запуск на настоящем стенде.

Первый запуск тестов в sandbox не смог открыть loopback-порт. Повтор с разрешённым локальным bind завершился успешно; это ограничение среды не записано как дефект упражнения.

## Как воспроизвести локальные проверки

Команды выполняются от корня репозитория:

```sh
python3 -m unittest discover -v -s backend-devops-theory/tests
python3 backend-devops-theory/assets/examples/mechanisms.py all
python3 backend-devops-theory/assets/review-benchmark/benchmark.py validate
python3 backend-devops-theory/assets/labs/lab.py list
```

Для отдельного упражнения создать новый каталог через `prepare`, прочитать его `ASSIGNMENT.md`, затем вызвать `check`. Авторский цикл включает дефект, исправление и повторный reset; успешный `prepare` сам по себе не подтверждает работоспособность стенда. Команды и необходимые параметры каждой среды находятся в инструкции лабораторий.

На момент первичной проверки оставался прогон Linux/Docker/kind; его результаты теперь вынесены в продолжение отчёта выше. Отдельный проверяющий может получить слепой экспорт корпуса; его замечания оцениваются по классификации и содержанию, а не только итоговому баллу.
