Продолжаем часть 08/3: идемпотентность, практика v1, полный маршрут 30 тем / 92 части. Теория этой части уже выдана. R1 сохраняю закрытым: прежний проверяющий установил независимость покупателей по коду; это историческая проверка без указанной даты.

По R2 есть существенный конфликт. В основной записи он открыт; запись A утверждает «R2 closed, C2 проверен, практика принята», запись B — «R2 open, C2 не проверен, нужен повтор ревью». У A и B нет дат и хешей, порядок записей не задаёт хронологию. Не установлено, к какой из них относится submission.py и является ли он последней сдачей. Поэтому текущий статус R2 — unknown, статус приёмки практики — «не проверено». Обе записи сохраняю до уточнения.

Доступную часть проверил сейчас локально: Python 3.12.3, Darwin 25.6.0, команда python3 -B с загрузкой submission.py через compile/exec в памяти. Проверил два покупателя с одним ключом, повтор одинакового тела и повтор изменённого тела. PostgreSQL и Docker не использовались.

- C1 — подтверждено для приложенного файла: alice и bob с одним key-1 получают разные результаты, в state остаются две записи. Это согласуется с сохранённым закрытием R1.
- C2, одинаковое тело — подтверждено для приложенного файла: повтор alice/key-1 с amount=1 возвращает тот же результат.
- C2, изменённое тело — обнаружена ошибка в приложенном файле, submission.py:3–4: после amount=1 вызов с теми же alice/key-1 и amount=3 возвращает {'id': 1, 'payload': {'amount': 1}} вместо ValueError. Причина — безусловный возврат сохранённого результата до проверки тела. Это нарушение обязательного критерия C2; направление исправления — проверить соответствие тела перед возвратом при повторном ключе.

Этот запуск описывает именно предоставленный файл и не устанавливает, какая историческая запись о R2 актуальна. Новых требований к заданию не добавляю; практика и курс не объявляются завершёнными, понимание ученика по восстановлению записей не оценивается.

Следующий шаг: уточни, является ли приложенный submission.py последней сдачей по R2; если нет, предоставь актуальную версию с относящимся к ней ревью. Пересказывать остальные занятия не нужно. После установления версии повторно проверим R2 и независимость покупателей с сохранением ID R1 и R2.
