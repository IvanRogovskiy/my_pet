# Восстановление, сложные сдачи, независимые оценки и CI

Выполнены четыре направления улучшения курса: неблагоприятные состояния новой сессии, усложнённые сдачи с резервным контрольным набором, независимая перепроверка прежних оценок и автоматические проверки репозитория. Реальный ученик в этой работе не участвовал по запросу пользователя.

Все первые ответы сохранены. [Результаты](results.json) пересчитываются по зафиксированным входам и внешним оценкам, а не генерируются повторно. [Основной протокол](protocol.json), [протокол отдельной коррекции](correction-protocol.json) и [замечания к реализации](implementation-findings.json) сохраняют различия между первым результатом, исправлением инструмента и повторной проверкой.

## Восстановление после потери контекста

Новые случаи проверены по одному разу в отдельных свежих контекстах. Версия первого прохода — `teaching-2026-10-17.1`.

| Случай | Что проверяется | Точное совпадение состояния | Независимая смысловая оценка |
| --- | --- | --- | --- |
| RS04 | Сдача потеряна, история замечаний осталась | Да | 4/4 |
| RS05 | PROGRESS оборван, есть отдельное последнее ревью | Да | 4/4 |
| RS06 | Недатированные ревью противоречат друг другу, версия сдачи неизвестна | Да | 4/4 |
| RS07 | Ученик явно сменил маршрут и отложил прежнюю практику | Нет: к коду части добавлено название | 4/4 |

Все четыре записи допустимы по исходной схеме; полное буквальное совпадение — 3/4, смысловые критерии — 16/16. В RS06 `unknown` сохраняет конфликт истории; он не означает закрытия замечания или приёмки работы. В RS07 новая практика остаётся невыданной, а незавершённая старая сохраняется отдельно.

Редакция `teaching-2026-10-17.2` явно требует только код `NN/N` в `recovered.part`. Отдельный первый ответ нового контекста на исправленный контракт совпал по всем полям; смысловая оценка координатора — 4/4. Это отдельная проверка, не замена первого RS07 и не независимая повторная смысловая оценка. Первоначально выданный пример коррекции содержал уже недопустимый заполнитель; выдача сохранена без изменений. Unit-тест выявил это, в текущем экспорте пример исправлен и отмечен как условный.

Прежние редакции `.14.1` и `.14.2` поддерживаются. Их исторические ошибки формата и оценки не исправлялись задним числом.

## Сложные сдачи и покрытие дефектов

Добавлен `advanced-2026-10-17.1`: восемь development-сдач AD01–AD08, включая корректные альтернативы, несколько независимых ошибок в одной работе, слабый конкурентный тест и свидетельство от прежнего исходника. Четыре случая AH01–AH04 зарезервированы для будущего сравнения. Они не выдавались преподавателю; авторские unit-тесты их проверяют, поэтому это не секрет от автора репозитория.

Первый проход: **7/8 совпадений классификации**, ни одной ошибочно отклонённой корректной работы. Для дефектов кода TP/FP/FN = **3/0/0**; это число работ, а не отдельных ошибок. Внешняя оценка с привязкой к конкретным замечаниям подтверждает **6/6 отдельных дефектов**, включая дефект теста AD05. Все восемь объяснений получили 2/2 по каждой из четырёх шкал, суммарно 64/64.

AD06 классифицирован преподавателем как `environment`, авторский ключ — `hypothesis`. Отзыв правильно сохраняет обязательный Linux runtime непроверенным и запрашивает свидетельство для текущего исходника. Ключ после ответа не менялся; результат остаётся 7/8. Высокая смысловая оценка не устраняет это расхождение классификации.

[Метод независимого оценщика](assessment-templates/evaluation-method.md) содержит собственные локальные пробы и границы выводов. Ему были доступны критерии и авторские гипотезы; эта оценка не слепая к ключам.

## Независимая перепроверка прежних оценок

До новых оценок выбраны [8 из 44 старых отзывов](calibration-selection.json) разных типов. В отдельный свежий контекст переданы задания, код, отзывы и общая рубрика без прежних баллов, названий профилей и авторского ключа. Сопоставление с оригиналами осталось вне выдачи.

Все **32/32 оценки совпали**, средняя абсолютная разница по каждой шкале — 0. Все выбранные прежние и повторные баллы равны 2; эта выборка не проверяет способность рубрики различать слабые отзывы и не доказывает отсутствие общей систематической ошибки двух оценщиков. Исходные баллы не заменены повторными.

Первый JSON оценщика содержит SHA256 сырых байтов выдачи, а образец — SHA256 канонического JSON. Порядок событий сохранён в [методе](calibration/second-method.md). Сравнение проверяет точную связь обоих представлений с одним пакетом и сообщает `rating_hash_kind=file_bytes`; первый JSON не переписан. Новые экспорты прямо определяют канонизацию. [Собственный скрипт оценщика](calibration/probes/probe.py) и [его журнал](calibration/probes/probe-results.json) скопированы из временного каталога с проверкой хешей, записанных в первом методе.

## CI и фактические проверки

[Workflow](../../.github/workflows/course.yml) запускает быстрые тесты, совместимость исторических записей и целостность отчётов при push/PR. Матрица: Ubuntu 24.04 / macOS 15 и Python 3.11 / 3.12. Ручной запуск отдельно включает Linux HTTP/TLS/права файлов и PostgreSQL/RabbitMQ. Actions закреплены по SHA, права токена ограничены чтением. [Инструкция](../../backend-devops-theory/references/course-ci.md) описывает команды и остановку принадлежащего запуску стенда.

| Фактически выполнено локально | Результат | Свидетельство |
| --- | --- | --- |
| Быстрые тесты, macOS, Python 3.12.3 | 117/117, без пропусков | [Последний журнал](tests-fast-macos-final-after-contract.txt) |
| Быстрые тесты, Linux Docker, Python 3.12.14 | 117/117, без пропусков | [Журнал](tests-fast-linux-final.txt) |
| Linux runtime, UID 10001, cryptography 50.0.2 | 6/6, без пропусков | [Сводка фактического запуска](runtime-linux.json) |
| B07 / B08R / B08I / B17, реальные локальные сервисы | Для каждого bad/reference/reset = 1/0/1 | [Сводка](backend/audit.json), отдельные 12 проб в backend/ |
| Целостность и пересчёт отчётов, macOS и Linux Docker | 518 прежних + 159 новых файлов; прежние результаты сохранены | [Проверки и хеши исходников](verification.json) |

Структура workflow проверена YAML-парсером, скилл прошёл `quick_validate.py`. GitHub Actions в этой работе не запускался: нет коммита и push. Python 3.11 и hosted-матрица остаются заявленной конфигурацией, не фактически пройденными средами. Linux Docker не равнозначен конкретному hosted runner.

Начальная ошибка быстрого набора сохранена в `tests-fast-macos.txt`: sandbox запретил loopback. Этот тест отнесён к runtime, где он выполнен. Первый backend-аудит столкнулся с блокировкой ещё выполнявшейся проверки здоровья; после её завершения отдельный последовательный аудит прошёл. [Обе попытки](backend-attempts.json) сохранены. [Стенд остановлен](backend/stop.json), volumes сохранены согласно его жизненному циклу.

## Воспроизведение и ограничения

Из корня репозитория:

```sh
python3 -B docs/course-hardening-2026-10-17/reproduce.py
python3 -B scripts/course_ci.py evidence
```

Первая команда использует снимки оценщиков из `evaluators/`, проверяет привязку входов, ответов и оценок, сопоставление с прежними отзывами и результаты отдельных backend-проб. Итог должен совпасть с `results.json`. Вторая дополнительно проверяет SHA256 и точный состав обоих отчётов, пересчёт прежнего отчёта и совместимость текущего оценщика со старыми записями. Исторический отчёт содержит 518 неизменённых файлов. Состав и хеши этого отчёта — в `manifest.json`, сведения о проверенных исходниках — в `verification.json`.

Преподаватели и оценщики — модели семейства GPT-6 в отдельных контекстах; точная runtime-ревизия не раскрыта. Границы чтения задавались инструкцией при общем файловом пространстве, не технической изоляцией. Новые случаи имеют по одной попытке; один удачный ответ не устанавливает устойчивость. Повторная оценка не равнозначна человеку или модели другого семейства. Хеши удостоверяют неизменность записей, а не истинность смысловых суждений. Человеческий учебный эффект и перенос на другие работы этим опытом не измерены.
