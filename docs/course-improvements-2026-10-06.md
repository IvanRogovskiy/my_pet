# Внедрение улучшений курса — 6 октября 2026

Основание: практический аудит, 32 группы предложений и 8 уточнений процесса ревью, плюс сравнительный анализ восьми похожих курсов. Исходный анализ сохранён в `course-audit/2026-10-01/SKILL-IMPROVEMENTS.md`; это исторический документ, результаты старого прогона не переписаны как результаты новой редакции.

По прямому указанию пользователя исключены подготовительный блок перехода Java → Python, отдельный короткий вводный проект API → PostgreSQL → Docker → CI/CD и контрольные Git-теги по этапам. Из смешанных предложений сохранены разрешённые части: честные форматы обучения, упражнения в существующих темах, журнал редакций и самостоятельное расширение уже изученного примера.

## Что сохраняет логику

Остаются 30 обязательных тем, 92 части теории и 6 факультативов по явному выбору. Изменения конкретизируют существующий OrderFlow. Малые упражнения входят в практику, интеграционные занятия входят в блоки; второй вводный проект не создаётся. Redis не требуется до 16, Terraform до 24, Kubernetes до 27; платёжный возврат относится к 30. В SQL темы 04 возвраты представлены только готовыми входными данными агрегирования.

Уточнены предпосылки: тема 08 явно учитывает Django/admin и права (05–07), тема 24 — GitLab CI (12). Всё это раньше соответствующих тем. Изначальная оценка 578 часов сохранена как исторический ориентир, не обещание срока новой редакции. Подготовку, отказы, ревью и исправления теперь требуется учитывать отдельно.

| Сохранность существующих записей | Совпали хеши 671 Markdown/JSON-документа в learning и старом аудите; личный прогресс не пересчитан |
| Формат | Markdown fences сбалансированы, завершающих пробелов нет; `git diff --check` без ошибок |

Ручная сверка сценариев по тексту инструкций: «полный курс → вопрос о 2 часах → продолжай» сохраняет полный маршрут; отсутствие VM оставляет Linux-критерий непроверенным; новый критерий получает новую версию; сбой импорта/селектора/polling не объявляется дефектом приложения; пауза после partial apply требует чтения фактического состояния; открытое production-ограничение вне задания не создаёт бесконечную приёмку. Это самопроверка автора правок, без независимого оценщика и отдельного диалогового прогона скилла.

При сверке исправлены две неоднозначности: неопределённая «рабочая область» оператора заменена явным правом в примерном контракте; CI-пример обхода gate теперь требует подходящей ёмкости executor и фактического воспроизведения, а не полагается на 5-секундную задержку как гарантию.

Порядок CI lint, HTTP backend, cloud-init, SSH connection/check-mode Ansible, Django static и Kubernetes PDB/probes сопоставлен с первичными документациями; ссылки размещены рядом с инструкциями. Это проверка технических формулировок, не подтверждение запуска стендов.

Полный практический курс новой редакции, hosted CI, Linux/browser/облачные опыты повторно не запускались. Инфраструктура не создавалась и не включалась. Эффективность обучения человека и независимая способность скилла обнаруживать дефекты остаются предметом последующего учебного/слепого прогона, а не заявленным результатом этой правки.
