## Ответ преподавателя (дословно)

Практика 08/3 v1 пока требует исправлений. Я проверил предоставленный `submission.py` локальным Python 3.12.3: первое создание и повтор того же тела проходят; два других сценария воспроизвели ошибки.

| Критерий | Результат |
| --- | --- |
| C1: создание в области (buyer, key), независимость покупателей | Обнаружена ошибка R1. Первое создание подтверждено. |
| C2: повтор того же тела без новой записи; ValueError при другом теле | Обнаружена ошибка R2. Повтор того же тела без изменения state подтверждён. |

**R1 — область ключа, `submission.py:2–5`.** На пустом `state` вызови сначала `submit(state, "alice", "k1", {"item": "book"})`, затем `submit(state, "bob", "k1", {"item": "pen"})`. По C1 ожидаются две независимые записи и результат с `pen` для Bob. Фактически остаётся одна запись, Bob получает результат Alice с `book`. Причина видна в коде: поиск и запись используют только `key`, а `buyer` не участвует. Это нарушает обязательную независимость покупателей.

**R2 — конфликт тела, `submission.py:2–3`.** На новом пустом `state` выполни те же два вызова с покупателем `"alice"` в обоих. По C2 второй вызов должен вызвать `ValueError`. Фактически исключения нет: возвращается прежний результат с `book`; состояние не меняется. Немедленный возврат при найденном ключе не различает повтор и конфликт, поэтому изменённый запрос молча принимается как прежний.

Одна подсказка для следующей попытки: начни с R1 — подумай, какие данные должны вместе определять один адрес записи в `state`, чтобы совпадение `key` у разных покупателей не приводило к совпадению этого адреса. Пришли свою правку; R2 пока остаётся отдельным открытым замечанием.

Новых обязательных требований и необязательных улучшений не добавляю. PostgreSQL и Docker не входят в эту приёмку; изменение внешних аргументов после вызова также исключено заданием.

Сохранение включено локально в `learning/`, без commit/push. Зафиксированы полный маршрут 30 тем / 92 части, теория 08/3 как уже выданная по твоему сообщению, первая сдача v1 и открытые R1/R2.
