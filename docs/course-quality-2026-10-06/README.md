Эти результаты не меняют зачёты реального ученика.

## Что показали новые backend-опыты

- **B07:** дефект разрешал чужие GET/PATCH и менял защищённую запись. Исправление одновременно запрещает чужое действие и разрешает собственное; фиктивный deny-all не закрывает матрицу.
- **B08R:** два PostgreSQL backend PID и барьер воспроизвели два заказа при stock=0. Исправленный условный UPDATE даёт один заказ. Отдельная [альтернатива SELECT FOR UPDATE](backend/row-lock/result.json) также принята — эталон не навязывает форму SQL.
- **B08I:** ошибочный check-then-insert получает UniqueViolation при повторе, путает владельцев и игнорирует изменённое тело. Исправление возвращает один id двум конкурентным попыткам, не смешивает покупателей и откатывает shortage.
- **B17:** publisher завершён кодом 17 после broker confirm до DB mark; consumer — кодом 18 после commit до ack. RabbitMQ реально повторяет доставку. Ошибочный consumer применяет эффект 3 раза, исправленный — 1. Дополнительный [дефект раздельных транзакций](backend/split-receipt/result.json) обнаружен: нормальный replay проходит, но при отказе эффекта остаётся receipt, и критерий атомарности проваливается.

Это ограниченные механизмы, не подтверждение всего production приложения. B07 использует заданную identity fixture, B08I не проверяет HTTP 409/canonical JSON, B17 не закрывает Celery routing/HA/throughput. Границы перечислены до сдачи в [условиях лабораторий](../../backend-devops-theory/assets/backend-labs/README.md).

## Исправления материалов и инструментов

1. N+1 больше не предъявляется обязательным дефектом темы 05 до объяснения в 08/4.
2. Ранние части получили явные предоставляемые fixtures: Linux/HTTP до разработки своего сервиса, ручная browser acceptance, HTML/JS-клиент WebSocket, PVC в 27/2. Поздние инструменты не стали скрытыми предпосылками.
3. Первые проверки 06 не требуют pytest fixtures; лимит одного процесса 07 не выдаётся за распределённый Redis limiter. Сборка CPython/GIL названа явно.
4. Тема 09 использует подготовленные мутанты в отдельной копии; намеренное повреждение рабочего кода ученика не является обязательным условием.
5. Для всех 92 частей записана конкретная граница доказательства: теория, статический анализ, модель, реальный runtime и результат ученика не смешиваются.
6. В readiness RabbitMQ исправлен UID: root-проверка создавала недоступный брокеру `.erlang.cookie`. Диагностика теперь выполняется пользователем rabbitmq.
7. Авторский backend runner создаёт evidence при prepare. Traceback самого проверяющего без валидного JSON трактуется как exit 2, не «дефект найден».
8. Linux bootstrap запускает D-Bus/logind до loginctl и сохраняет supplementary groups через runuser; одного `--user UID:GID` было недостаточно для чтения журнала.
9. Проверка concurrency требует два разных backend PID, заявленный уровень изоляции и факт прохождения барьера; отдельный fault injection проверяет общий rollback receipt/effect.
10. GET GitLab проекта сначала сокращается до allowlist. Во время первоначального чтения агент ошибочно вывел поле legacy runner registration token; пользователю сообщено, запрошено отдельное решение о сбросе. Значение не перенесено в файлы; authentication token runner не менялся. На момент отчёта решение о ротации не получено.

## Ограничения и дальнейшая приёмка

Слепое ревью — один небольшой синтетический набор; содержательные объяснения дополнительно оценивал агент автора, а не человек. Диалог — один прогон одной модели; первоначальный неизменяемый snapshot материалов до первого хода не был создан, что явно отражено в оценке. Новый протокол требует его при повторе.

Карта 92 частей — содержательный аудит **спецификаций**, не утверждение о наличии 92 написанных полных лекций. Шесть существующих подробных материалов остаются опорой для выбранных сложных частей, остальные лекции разворачиваются скиллом во время обучения.

Stands закрепляют image digests, CLI release versions/checksums и Python dependencies; Debian apt-пакеты фиксируются по фактическому результату, но не выдаются за герметичный snapshot. На другом CPU/OS необходим отдельный runtime-прогон. Локальный kind не доказывает SSH/reboot VM, cloud IAM, HA, CNI enforcement или весь production CD.

Следующий шаг, который требует человека: провести подготовленный пилот, сохранить собственные ответы/попытку участника и на их основе уточнить ясность урока и ревью. Никакие новые облачные расходы для этого комплекта не создавались.
