| ID | Наблюдение | Вывод и следующий шаг |

| F01 | 6/6 execution имеют тип array вместо string | Несоответствие формату записи. В следующей редакции выдачи нужен явный JSON-пример с типами, либо осознанно версионированная поддержка списка. Текущий check не ослаблен ради результата |

| F03 | Шаблон смысловой оценки раньше требовал успешный check | Исправлено: оценивать можно исходный непустой response, строго связанный с выдачей; ошибка формата и хеш всего исходного JSON сохраняются отдельно. Две новые регрессии, всего 14/14 целевых тестов |

Это полезная подсказка и не доказанный дефект преподавания: профиль допускает предложенное преподавателем расписание. Файлы format-diagnostic.json — производные диагностические результаты, не исправленные ответы модели и не новый успешный прогон.

## Метод и доказательства

Каждый агент получил только собственную выдачу и общие инструкции преподавателя. Родительская история, авторские критерии, соседние кейсы и прежние ответы не передавались. Сохранены точные поручения запуска и возвращённые канонические ID: [run.json](run.json). Все шесть ID различаются. Файловая система общая: ограничение чтения задано инструкцией, а не отдельной защищённой файловой средой. Метод каждого агента лежит рядом с его answer.json.

Предъявленные входы побайтово совпали с подготовленными ранее хешами; после ответов также проверена неизменность. Исходная подготовка: [pre-run-verification.json](pre-run-verification.json). В inputs сохранены сами выдачи, в outputs — первые ответы, методы и дополнительные артефакты агентов. Оценщик до правки сохранён в evaluator, после правки — в evaluator-after. Разница относится только к возможности отдельной смысловой оценки; исходные задания, rubric и check не исправлялись под ответы.

RS03 выполнил локальные вызовы submit в памяти: разные покупатели дали две записи; изменённое тело вернуло старый результат вместо ValueError. Остальные пять ответов ограничились чтением. Прогон RS03 отдельно воспроизведён координатором: [coordinator-probe.json](coordinator-probe.json). PostgreSQL, Docker и облако в этих шести опытах не запускались.

Оценки критериев с конкретными основаниями лежат в outputs/*/semantic-assessment.json и привязаны к каноническому SHA256 полного исходного ответа. Команды проверки оценки — semantic-assessment-check.json. [Общая сводка](assessment-summary.json) сохраняет формат и смысл раздельно. [Тесты оценщика](tests-evaluator.txt) проверяют, что неудачный формат не теряет смысловую оценку, а изменение исходного ответа делает прежнюю оценку недействительной.

Повтор исходной проверки, ожидаемый код 2:

```sh
python3 docs/teaching-evaluation-2026-10-14/evaluator/teaching.py check docs/teaching-evaluation-2026-10-14/inputs/RS01 docs/teaching-evaluation-2026-10-14/outputs/RS01/answer.json
```

Проверка целостности внешней оценки исходного ответа, ожидаемый код 0; смысл заметок программа сама не оценивает:

```sh
python3 docs/teaching-evaluation-2026-10-14/evaluator-after/teaching.py assess docs/teaching-evaluation-2026-10-14/inputs/RS01 docs/teaching-evaluation-2026-10-14/outputs/RS01/answer.json --assessment docs/teaching-evaluation-2026-10-14/outputs/RS01/semantic-assessment.json
```

Один ответ на сценарий не доказывает устойчивость всех будущих диалогов. RS начинает с подготовленных автором checkpoints и проверяет их чтение в новом контексте; качество записи состояния в предшествовавшей живой сессии этим не проверено. TR-упражнения, RV20 и сравнение HC12 в этом прогоне не запускались. Настоящие learning/ и прежний course-audit не изменялись.
