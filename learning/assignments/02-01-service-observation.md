# Тема 02, часть 1: найти службу и объяснить её доступ

Уточнение ранее выданного задания. Выполнение пользователем пока не подтверждено.

## Начало

Нужна учебная Linux-машина с systemd. Если её наличие неизвестно, сначала уточнить среду. Терминал macOS не подходит для выполнения команд systemctl на локальной машине. Подготовка VM и SSH относится к дальнейшей практической работе темы; здесь её не считаем уже выполненной.

Служба — управляемый systemd запуск программы. «Выбрать существующую службу» значит получить список реально запущенных служб и скопировать одно точное имя из этого списка.

## Если Linux с systemd доступен

1. В терминале этой Linux-машины выполни `systemctl list-units --type=service --state=running --no-pager`. Здесь `--type=service` оставляет службы, а `--state=running` — запущенные.
2. Если в списке есть `systemd-journald.service`, выбери его. Иначе пришли названия служб из списка, чтобы выбрать понятный пример. Если список пуст или команда не работает, пришли текст ошибки и название ОС; не подставляй вымышленное имя.
3. Выполни `systemctl status ИМЯ.service --no-pager`, заменив `ИМЯ.service` точным именем. Найди основной PID в выводе. Если его нет, укажи это в результате и пришли статус для разбора.
4. Для найденного PID выполни `ps -p НОМЕР -o pid,user,args`. Запиши пользователя процесса. Посмотри последние сообщения через `journalctl -u ИМЯ.service -n 20 --no-pager`. Если журнал недоступен, зафиксируй ограничение; пустой вывод не означает отсутствие ошибок.
5. Создай в корне учебного проекта текстовый файл `service-check.md` в формате Markdown. Включи имя службы, команды, строки о состоянии и PID, пользователя процесса и 3–5 относящихся к службе строк журнала. Секреты и посторонние персональные данные не включай. Пришли содержимое файла в чат на проверку.

Проверка выбора файла, который служба читает, будет отдельным шагом после установления её назначения. Не нужно угадывать такой файл по имени службы.

## Если Linux сейчас нет

Выполни [учебный разбор прав каталогов](../lessons/0001-linux-directory-access.html). Это симуляция: службы не запускаются и права ОС не меняются. В чат пришли результат упражнения и своими словами объясни причину отказа. Этот результат не заменяет выполнение команд на Linux.

## Критерии

- Служба выбрана из фактического списка, имя не выдумано.
- Состояние и пользователь процесса подтверждены выводом команд; отсутствующий PID или недоступные данные явно отмечены.
- Файл содержит перечисленные сведения; журнал и состояние службы различаются.
- Ревью отдельно обозначает проверенное, ошибки и непроверенные критерии. Симуляция может подтвердить разбор примера, но не запуск и диагностику службы.
