# Новая сессия, подсказки и перенос

Редакция `teaching-2026-10-17.2`. Семь RS-сценариев восстановления, три HS-сценария подсказок и шесть TR-упражнений на перенос. Авторские `teaching_cases.py`, `teaching_cases_v1.py`, `recovery_cases.py` и эта инструкция не выдаются участнику. Набор дополняет существующий 12-ходовый диалог; его входы и результаты сохраняются.

В редакции `2026-10-14.2` устранены неоднозначности выдачи: JSON Schema и пример записи явно требуют строку execution; фиксированный practice отделён от обязательного practice_note. HS02 измеряет **анализ** расписания, в том числе предложенного преподавателем: ученик должен сам назвать значения чтений или исход проверок. Самостоятельное построение расписания без опоры — другой критерий и здесь не заявляется. Старые ответы и рубрика .1 не переоцениваются по новым правилам.

Редакция `2026-10-17.1` добавляет четыре неблагоприятных состояния и статус замечания `unknown`: противоречие сохранено, его нельзя выдавать за закрытие или снятие. `2026-10-17.2` уточняет машинное поле `recovered.part`: только код NN/N, без названия темы. Все четыре редакции доступны через `--version`; старые выдачи проверяются по своему контракту. Три прежних RS остаются полным набором для редакций 14 октября, семь — для 17 октября. `practice` относится к текущей части; отложенные задания сохраняются отдельно в snapshot.

Из корня проекта:

```sh
python3 backend-devops-theory/assets/teaching-benchmark/teaching.py list
python3 backend-devops-theory/assets/teaching-benchmark/teaching.py export /tmp/course-rs01 --case RS01
python3 backend-devops-theory/assets/teaching-benchmark/teaching.py export /tmp/course-hs01 --case HS01
python3 backend-devops-theory/assets/teaching-benchmark/teaching.py export /tmp/course-tr02 --case TR02
```

Каталог должен отсутствовать. Экспорт содержит только текущий сценарий, prompt, формат ответа и manifest с SHA256. Для RS/HS включается профиль из текущих общих правил ревью, учебного состояния и подсказок с хешами исходников. Это явно ограниченный профиль преподавателя, не прогон всего курса; ссылки на отсутствующие файлы открывать нельзя. TR выдаёт только условие ученику. Оригинальные входы неизменны; ответ и снимок результата сохраняются рядом, вне выдачи.

response.schema.json содержит обязательные поля, типы и допустимые статусы; response.example.json — заполнители формы, не ответ на задание. Для старой выдачи использовать `export ... --case RS01 --version teaching-2026-10-14.1`; check/assess автоматически выбирают прежний контракт и рубрику по manifest. Замороженные исторические входы проверяются без пересоздания. Новая выдача .1 всё равно использует текущий общий профиль; для воспроизведения старого профиля нужен сохранённый снимок. Смешивать версии в check-resume-run нельзя.

## Проверка восстановления

| Сценарий | Момент остановки |
| --- | --- |
| RS01 | В середине реализации, первая попытка ещё не сдана |
| RS02 | После ревью с открытым R1 и непроверенной PostgreSQL-конкуренцией |
| RS03 | После частичного исправления: R1 закрыт, R2 открыт |
| RS04 | Последняя сдача потеряна, история ревью сохранилась |
| RS05 | PROGRESS оборван, есть независимая запись последнего ревью |
| RS06 | Две записи противоречат друг другу, версия сдачи не установлена |
| RS07 | Пользователь меняет маршрут и откладывает прежнюю практику |

Для каждого RS нужен отдельный новый контекст без истории разговора и без ответов других сценариев. Передать только каталог выдачи и просьбу выполнить TASK.md. Не пересказывать правильную точку продолжения в запросе. Записать реальный идентификатор контекста и способ запуска. Если отдельные агенты не разрешены, подготовить и технически проверить комплект, а фактическое восстановление оставить «не проведено»; нельзя заменить его чтением ключа тем же автором.

Проверяющий восстанавливает состояние из файлов и даёт ученику один следующий шаг. В записи сохраняются дословный response, recovered и полные PROGRESS/NOTES после ответа. По исходным файлам и ответу оценить, сохранены ли маршрут, версия, закрытые и открытые замечания; не придуманы ли зачёт или запуск. Поле fresh_context — заявление ведущего, не техническое доказательство независимости. Идентификаторы RS-сессий должны различаться; командой check-resume-run можно выявить повторный ID.

## Проверка подсказок

HS01: неясно условие; HS02: неверное понимание atomic; HS03: понимание верное, но код изменяет состояние до отказа. Во всех случаях сохранить настоящий ответ преподавателя, число предложенных действий и границу помощи. Успех оценивается по объяснению и уместному следующему шагу, не поиском слов «подсказка» или «самостоятельно».

Для оценки вариаций менять конкретные формулировки/код и выпускать новую редакцию. Для оценки воспроизводимости допускаются заранее объявленные повторы неизменной выдачи в новых контекстах; они не доказывают перенос на другие формулировки. Ученик может прямо попросить готовое решение; этот запрос не следует выдавать за нарушение самостоятельности. Эти три сценария такой просьбы не содержат.

## Запись и оценка

Формат записи дан в экспортированном TASK.md. session содержит имя/известную версию модели (или участника без персональных данных), дату, ID и происхождение контекста. Для синтетических ответов не указывать human. execution описывает реальные команды и результаты либо static_only с границей анализа.

```sh
python3 backend-devops-theory/assets/teaching-benchmark/teaching.py check /tmp/course-rs01 /tmp/rs01-answer.json
python3 backend-devops-theory/assets/teaching-benchmark/teaching.py assessment-template /tmp/course-rs01 /tmp/rs01-answer.json > /tmp/rs01-assessment.json
python3 backend-devops-theory/assets/teaching-benchmark/teaching.py assess /tmp/course-rs01 /tmp/rs01-answer.json --assessment /tmp/rs01-assessment.json
```

check проверяет версию, входной manifest, точность prompt, формат, декларацию новой сессии и структурированные поля восстановленного состояния. Несовпадение состояния даёт код 1, ошибочный формат — 2. Непустой response или правильные поля не доказывают смысловую правильность текста и snapshot. Их проверяет отдельный оценщик по assessment-template; шаблон открывает авторскую рубрику только после фиксации ответа. До оценки все критерии pending, они не считаются успехом.

Оценщик указывает human/model/self_review. Каждому критерию присваивает confirmed/error/unverified с конкретной цитатой или местом в snapshot и основанием. После изменения ответа прежняя оценка отклоняется по SHA256. Автор, знающий ключи, не называется независимым оценщиком. Для TR оценивается собственное объяснение ученика и план проверки; результаты агента остаются симуляцией.

Смысловую оценку можно заполнить и при ошибке формата записи: assessment-template/assess требуют точную привязку к выдаче и непустой дословный response, но не успешный check. Первоначальная ошибка check остаётся отдельным результатом. Внешняя оценка связывается с полным исходным JSON, включая ошибочно оформленные поля; исправленная или нормализованная копия требует другой оценки. Это позволяет оценить текст без переписывания первого ответа под валидатор.

Для проверки полного набора восстановлений одной редакции создать index.json: `{"runs":[{"bundle":"RS01","answer":"RS01-answer.json"}, ...]}`. Пути относительны каталогу index.json. Затем:

```sh
python3 backend-devops-theory/assets/teaching-benchmark/teaching.py check-resume-run /tmp/resume-run/index.json
```

Сохранить все ответы и оценки, включая неудачные. Не редактировать ответ до успешного score. Исправленный ответ сохранять новой попыткой. Технические тестовые записи всегда подписывать synthetic; они не являются проведённым диалогом или доказательством обучения.
