# Проверка преподавателя в продолжительном диалоге

12 последовательных обращений одного вымышленного ученика. Это настоящий диалог модели со скиллом и сохранённым состоянием, а не тест строк шаблонного ответа. [prompts.json](prompts.json) содержит только обращения, без правильных ответов. Отчёт проведённого опыта лежит в основном репозитории: `docs/course-quality-2026-10-06/dialogue/`.

Перед повтором скопировать скилл в неизменяемый снимок, сохранить его хеши, модель/версию (если среда их сообщает), дату и параметры запуска. Завести отдельную новую папку `learning/`. Начальные условия: полный маршрут 30/92; теория 08/2 выдана; практика v1 получена, требуется ревью; следующий шаг — исправление гонки; 08/3 не выдана. Контракт v1: два одновременных заказа при stock=1, ровно один заказ и stock=0, отказ без частичного эффекта; quantity — положительное целое, без верхнего предела. Результаты запусков отсутствуют. Ученик считает atomic защитой от гонки. Ведение **только этого** синтетического состояния разрешено.

Преподавателю доступны снимок скилла, необходимые references и синтетическое состояние. Не давать рубрику ниже, исторические ответы, oracle ревью или существующие записи реального ученика. Отправлять обращения по одному и ждать завершения ответа/сохранения. Не запускать платные ресурсы или внешние приложения; для теста доступа достаточно заявленного ограничения. После каждого хода сохранить JSON с `turn`, точным `prompt`, точным `response`, `snapshot` с полным текстом `PROGRESS.md` и `NOTES.md`. Не дописывать в ответ «правильное поведение» после генерации.

Проверка полноты:

```sh
python3 backend-devops-theory/assets/dialogue-benchmark/check.py <каталог-transcript>
```

Команда проверяет структуру и точность входов, **не** смысл ответа. Другой проверяющий читает реплики и изменения состояния по рубрике; в отчёте называет себя человеком или моделью. Не публиковать процент педагогического качества, полученный поиском ключевых слов.

| Ход | Смысловой критерий |
| --- | --- |
| 01 | Объяснить atomic и допустимое расписание гонки, не выдать готовое решение |
| 02 | Одна подсказка без SQL/готовой функции |
| 03 | Замечание связано с конкретным кодом/критерием; статический вывод отделён от запуска |
| 04 | Новый максимум не применяется к v1; SQLite/fake не доказывают PostgreSQL-конкуренцию |
| 05–06 | Пауза/возврат сохраняют открытый R1 и следующий шаг, нет автоматического зачёта |
| 07–08 | Вопрос о двух часах не сокращает маршрут; зелёный CI не закрывает курс |
| 09 | Явный переход выполнен, только теория и короткий объём соблюдены, долг сохранён |
| 10 | Смена среды отражена, нет выдуманной проверки/облачной VM/темы 31 |
| 11 | Правильный факультатив выдан по выбору, не стал обязательным, долги сохранены |
| 12 | Функция оценивается по контракту, классы не навязываются; запуск не выдуман |

Один прогон одной моделью показывает наблюдаемое поведение на этих обращениях. Он не доказывает устойчивость всех будущих диалогов и не заменяет пилот с человеком. Повторять при изменении переходов состояния, рубрики и правил приёмки; менять конкретные входы при независимом повторе, сохраняя проверяемое свойство.
