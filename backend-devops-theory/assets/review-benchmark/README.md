# Набор работ для проверки преподавателя

Версия `2026-10-12.1`, 20 синтетических сдач. Нужен для калибровки ревью, не для оценки реального ученика. Подготовлены 7 работ с ошибками кода, 7 корректных вариантов, 2 дефекта теста, 2 ограничения/сбоя среды и по одному случаю нового требования и недостаточного доказательства конкуренции. Исходные RV01–RV12 сохранены; восемь новых работ основаны на полном прохождении курса.

| Работы | Что проверяется | Основание |
| --- | --- | --- |
| RV13–RV14 | Обнаружение перезапуска при `changed=0` и приёмка корректного сравнения состояния | F40 |
| RV15 | Зелёный последовательный тест, заявленный конкурентным; отсутствие доказанного дефекта бизнес-кода | F11, F12 |
| RV16 | Ошибка предоставленного преподавателем harness до вызова клиента | F05 и наблюдение гонки готовности новой TLS-лаборатории |
| RV17–RV18 | Потеря точности исходного JSON и корректная альтернатива с Decimal | F06, F08 |
| RV19–RV20 | Одинаковые суммы разных позиций и корректная агрегация по заказам | F07 |

Это авторская инструкция: проверяющему для слепого прохода выдаётся только экспорт.

## Проверить комплект и выдать работу

```sh
python3 backend-devops-theory/assets/review-benchmark/benchmark.py validate
python3 backend-devops-theory/assets/review-benchmark/benchmark.py export /tmp/of-review-blind
```

Validate выполняет наблюдаемые проверки авторских fixtures: Python, SQL в SQLite, порядок submit/result и воспроизведение ошибки подготовки во временном каталоге. Для RV09/RV11 проверяется только комплект. RV13/RV14 моделируют состояние службы; RV15 не запускает PostgreSQL; RV16 не выполняет TLS. Нельзя выдавать эти результаты за новые Ansible/systemd/PG/TLS-прогоны. Export требует нового каталога; выдаёт задания, код, приложенные материалы, общую рубрику и хеши, включая REVIEW.md. Ключи классификации, объяснения автора, `corpus.py`, `audit_cases.py` и рубрика оценивания объяснений в выдачу не попадают.

Проверяющий получает только экспорт и общие инструкции ревью курса. Если он уже видел `corpus.py` или написал эти работы, проход называется самопроверкой, а не слепым независимым ревью. Для слепого прохода нужен другой контекст без исходного ключа; запуск дополнительных моделей/API не является автоматическим действием экспортёра.

Результат сохраняется как JSON с массивом `reviews`; полный формат находится в экспортированном `REVIEW.md`. Критерии оцениваются отдельно от качества приложенного теста: реализация может соответствовать заданию, а тест нуждаться в исправлении. Стилистические советы не превращаются в блокирующие замечания. Новое бизнес-условие не применяется задним числом.

## Измерить результат

```sh
python3 backend-devops-theory/assets/review-benchmark/benchmark.py score /tmp/reviewer-answer.json
```

Score проверяет классификацию, итог, состояния критериев, поля карточки замечания и существование указанного файла/строки в выдаче. В отчёте: совпадения рубрики, отсутствующие работы, ошибки формата, TP/FP/FN для ошибок кода, precision/recall; отдельно списки `missed_code_defects`, `false_code_defect_claims` и `incorrect_rejections`. Последний список включает отклонённые корректные работы даже при метке `test_defect`, а не только `code_defect`. Дубли ID и неизвестные работы отвергаются; пропущенный настоящий дефект учитывается в FN. Число «20 совпадений» само по себе не является успешной оценкой преподавателя.

**Смысл объяснения скрипт не проверяет.** Проверяющий может угадать метку и дать неверное основание. Поэтому отчёт всегда сохраняет `human_review_required=true` и `explanation_verified=false`. Человек или отдельно калиброванный оценщик проверяет: указан ли настоящий файл/строка, воспроизводится ли замечание, соответствует ли оно C1, нет ли скрытого нового условия, объясняет ли подсказка причину и сохраняет ли самостоятельную работу. Не выдавать синтетический ответ из теста оценщика за реальное модельное ревью.

## Оценить объяснения и полезность обратной связи

```sh
python3 backend-devops-theory/assets/review-benchmark/benchmark.py assessment-template /tmp/reviewer-answer.json > /tmp/explanation-assessment.json
```

Другой проверяющий читает исходную выдачу, ответ, авторское основание и [рубрику качества объяснений](ASSESSMENT.md), затем заполняет отдельный JSON. В нём указаны имя/обозначение оценщика, вид проверки (`human`, `model`, `self_review`), версия и SHA256 ответа. После заполнения:

```sh
python3 backend-devops-theory/assets/review-benchmark/benchmark.py score /tmp/reviewer-answer.json --assessment /tmp/explanation-assessment.json
```

Четыре оценки 0–2 учитываются отдельно: правильность объяснения, доказательство, полезность следующего действия и сохранение самостоятельности. Для каждой требуется конкретное основание. Непроверенные строки остаются `pending`; их нельзя считать нулями или успешными результатами. `explanation_assessment` показывает покрытие и средние по каждой шкале, без общего «процента качества». Оценка к изменённому ответу или другой версии отвергается. Скрипт записывает внешнее суждение и не подтверждает его истинность; `complete` означает лишь заполнение всех работ.

## Повторить старый результат

```sh
python3 backend-devops-theory/assets/review-benchmark/benchmark.py score /tmp/reviewer-answer-v1.json --version 2026-10-06.1
```

`--version` также поддерживается в validate, export и assessment-template. Старая версия содержит 12 работ; новый набор не расширяет знаменатель старого отчёта без явного выбора. Если ответ содержит `benchmark_version`, она должна совпадать с выбранной. При отсутствии поля версия берётся из CLI (по умолчанию новая), поэтому для исторических ответов нужно явно указать старую версию. Старые отчёты и контрольные суммы не переписываются.

Для сравнения моделей сохранить имя/версию, дату, доступные инструменты, manifest выдачи, сырой ответ и ручную оценку объяснений. Повторить несколько запусков на неизменном комплекте; одну удачную попытку не считать гарантией. После раскрытия ключа использовать новые варианты с теми же инвариантами для повторной слепой оценки. Пакет не является защищённой экзаменационной системой: доступ к исходному репозиторию открывает ключ автора.
