# Набор работ для проверки преподавателя

Версия `2026-10-06.1`, 12 синтетических сдач. Нужен для калибровки ревью, не для оценки реального ученика. Подготовлены 4 работы с ошибками кода, 4 корректных варианта и по одному случаю дефекта теста, ограничения среды, нового требования и недостаточного доказательства конкуренции.

## Проверить комплект и выдать работу

```sh
python3 backend-devops-theory/assets/review-benchmark/benchmark.py validate
python3 backend-devops-theory/assets/review-benchmark/benchmark.py export /tmp/of-review-blind
```

Validate выполняет наблюдаемые проверки авторских fixtures. Для двух случаев с отсутствующей средой он проверяет комплект, но не выдумывает HTTP/PostgreSQL-запуск. Export требует нового каталога; выдаёт задания, код, приложенные материалы, общую рубрику и хеши. Ключи классификации, объяснения автора и `corpus.py` в выдачу не попадают.

Проверяющий получает только экспорт и общие инструкции ревью курса. Если он уже видел `corpus.py` или написал эти работы, проход называется самопроверкой, а не слепым независимым ревью. Для слепого прохода нужен другой контекст без исходного ключа; запуск дополнительных моделей/API не является автоматическим действием экспортёра.

Результат сохраняется как JSON с массивом `reviews`; полный формат находится в экспортированном `REVIEW.md`. Критерии оцениваются отдельно от качества приложенного теста: реализация может соответствовать заданию, а тест нуждаться в исправлении. Стилистические советы не превращаются в блокирующие замечания. Новое бизнес-условие не применяется задним числом.

## Измерить результат

```sh
python3 backend-devops-theory/assets/review-benchmark/benchmark.py score /tmp/reviewer-answer.json
```

Score проверяет классификацию, итог, состояния критериев и наличие полей карточки замечания. В отчёте: совпадения рубрики, отсутствующие работы, ошибки формата, TP/FP/FN для ошибок кода, precision/recall. Дубли ID и неизвестные работы отвергаются; пропущенный настоящий дефект учитывается в FN. Число «12 совпадений» само по себе не является успешной оценкой преподавателя.

**Смысл объяснения скрипт не проверяет.** Проверяющий может угадать метку и дать неверное основание. Поэтому отчёт всегда сохраняет `human_review_required=true` и `explanation_verified=false`. Человек или отдельно калиброванный оценщик проверяет: указан ли настоящий файл/строка, воспроизводится ли замечание, соответствует ли оно C1, нет ли скрытого нового условия, объясняет ли подсказка причину и сохраняет ли самостоятельную работу. Не выдавать синтетический ответ из теста оценщика за реальное модельное ревью.

Для сравнения моделей сохранить имя/версию, дату, доступные инструменты, manifest выдачи, сырой ответ и ручную оценку объяснений. Повторить несколько запусков на неизменном комплекте; одну удачную попытку не считать гарантией. После раскрытия ключа использовать новые варианты с теми же инвариантами для повторной слепой оценки. Пакет не является защищённой экзаменационной системой: доступ к исходному репозиторию открывает ключ автора.
