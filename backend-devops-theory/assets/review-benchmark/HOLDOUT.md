# Отдельный контрольный набор

Редакция `holdout-2026-10-14.1`: 12 новых работ HC01–HC12. Текущие RV01–RV20 остаются набором для настройки; исторические 12/20 имеют прежние версии и выдачу. Контрольные работы используют другие реализации и данные, включая правильные альтернативы, дефекты теста, ограничение среды, новое требование и непроверенную гипотезу.

Этот документ, holdout_corpus.py и семантическая рубрика — авторские материалы. Проверяющему дать только экспорт и неизменный общий профиль преподавателя без примеров/ключей контрольного набора. Не включать HC в учебные примеры или настройку подсказок. Автор, прочитавший ключ, не может выполнять независимый слепой прогон этой редакции.

```sh
python3 backend-devops-theory/assets/review-benchmark/review_holdout.py validate
python3 backend-devops-theory/assets/review-benchmark/review_holdout.py export /tmp/course-control
python3 backend-devops-theory/assets/review-benchmark/review_holdout.py score /tmp/control-answer.json
python3 backend-devops-theory/assets/review-benchmark/review_holdout.py assessment-template /tmp/control-answer.json > /tmp/control-assessment.json
python3 backend-devops-theory/assets/review-benchmark/review_holdout.py score /tmp/control-answer.json --assessment /tmp/control-assessment.json
```

validate выполняет только локальные контрпримеры Python. Среда Linux и crash/replay БД/брокера этим не подтверждаются. Формат reviews совпадает с RV; benchmark_version для HC обязателен. Export требует новый каталог; manifest содержит хеши всех входов, включая REVIEW.md. Напечатанный input_sha256 — SHA256 канонического manifest, не байтов его форматирования.

## Сравнение редакций преподавателя

До проверки заморозить baseline и candidate: скилл, используемые references, настройки и доступные инструменты. Сохранить manifest каждого снимка, его SHA256 и известное имя/версию модели. Выдать одинаковые входы в отдельные контексты без ключа и без ответов другой редакции. Одинаковый корпус и хеши не доказывают независимость сами по себе.

В каждый настоящий ответ добавить метаданные, не меняя reviews:

```json
{
  "benchmark_version": "holdout-2026-10-14.1",
  "run": {
    "name": "фактическая модель/версия или участник",
    "date": "дата запуска",
    "kind": "model",
    "key_seen": false,
    "tools": "фактически доступные инструменты и ограничения",
    "source_sha256": "64 hex: SHA256 manifest замороженных инструкций",
    "input_sha256": "64 hex: значение из export"
  },
  "reviews": []
}
```

kind: human/model/self_review. При key_seen=true допустим только self_review. Это заявляемое происхождение, не техническая аттестация. Метаданные добавлять до внешней оценки: её SHA256 связан со всем ответом.

```sh
python3 backend-devops-theory/assets/review-benchmark/review_holdout.py compare /tmp/baseline.json /tmp/candidate.json --assessment /tmp/baseline-assessment.json --candidate-assessment /tmp/candidate-assessment.json
```

Сравнение требует полные ответы с корректными ссылками и одинаковой контрольной выдачей. Отчёт сохраняет обе серии метрик и изменение TP/FP/FN/совпадений рубрики, ID ошибок и раздельную оценку объяснений. Пустые/незавершённые оценки остаются видимыми. Улучшение меток не перекрывает вредную подсказку; единого педагогического балла нет.

Зафиксировать число повторов до просмотра результата, хранить все попытки. Если исходные модели или инструменты различались, явно назвать это ограничением сравнения. После раскрытия ключа или использования результатов для целевых правок пометить редакцию как использованную для разработки и создать следующий контрольный комплект. Не выбирать удачные работы или запуски задним числом.

Начальное состояние этой редакции: подготовлена, реальные ответы преподавателя ещё не получены. Автотесты используют подписанные синтетические записи только для проверки оценщика. Секретности внутри исходного репозитория нет: экспорт отделяет выдачу, но права доступа обеспечиваются средой запуска.
