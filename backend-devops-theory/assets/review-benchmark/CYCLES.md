# Ревью → исправление → повторная проверка

Редакция `review-cycles-2026-10-13.1`: три самостоятельных сценария по три хода. Дополняет [20 отдельных сдач](README.md) и [проверку продолжительного диалога](../dialogue-benchmark/README.md). Их версии, входы и результаты не изменяются. Это комплект проверки преподавателя; синтетические сдачи не являются прогрессом настоящего ученика.

| Сценарий | Ход 1 | Ход 2 | Ход 3 |
| --- | --- | --- | --- |
| RC01, 08/3 | Две ошибки: область ключа и конфликт тела | Область исправлена, конфликт тела остаётся | Оба критерия выполнены |
| RC02, 07/2 | Администратор не читает чужой заказ | Доступ admin исправлен, buyer получил чужие заказы | Исправление сохраняет все три правила доступа |
| RC03, 06/1 | Ученик обоснованно оспаривает требование максимума 100 | В текущей ветке обнаружена правка по ошибочному требованию | Лишний предел удалён, ложное замечание остаётся снятым |

RC03 начинается с явно вымышленного прежнего ревью. Оно является заданным условием опыта, не наблюдавшимся ответом модели. Преподавателю нужно пересмотреть вывод по исходной v1. Нельзя приписывать ему реальное совершение этой ошибки до начала опыта.

## Проверить исходники сценариев

```sh
python3 backend-devops-theory/assets/review-benchmark/review_cycles.py validate
```

Команда исполняет девять авторских функций на локальных данных и сравнивает фактические результаты с критериями. В сценарии идемпотентности используются последовательные вызовы и dict; проверка прав — чистая функция; quantity — Python int. PostgreSQL, HTTP, конкуренция и производственное поведение не заявляются. Пользовательский код из произвольного transcript команда не исполняет.

## Провести три хода

Ведущий создаёт снимок скилла и сохраняет его хеши, дату, сведения о преподавателе и доступных инструментах. Каждый сценарий начинает с отдельного синтетического состояния. Для слепого прохода проверяющий получает только выдачу, общие инструкции скилла и уже выданные материалы; этот документ и `cycle_corpus.py` ему не показывают. Знание авторских ключей означает самопроверку.

```sh
python3 backend-devops-theory/assets/review-benchmark/review_cycles.py export /tmp/rc01-turn1 --cycle RC01
```

Выдача содержит неизменную карточку задания, **только текущую** версию submission.py, сообщение ученика, начальную историю, предыдущий transcript и шаблон ответа. Все файлы перечислены в manifest с SHA256. Не передавать следующую сдачу заранее. Ключи и будущие исправления не экспортируются.

Преподаватель отвечает на prompt.txt. Ведущий сохраняет дословный ответ и фактические снимки отдельного PROGRESS.md/NOTES.md в копию answer-template.json, например `/tmp/rc01-after1.json`. В reviewer указываются имя/версия, дата и вид проверки: human, model либо self_review. Структурированный review должен отражать сам ответ, а не правильные ответы автора. Пустой шаблон не считается проведённым ходом. Прошлые ответы и снимки после записи не редактировать.

```sh
python3 backend-devops-theory/assets/review-benchmark/review_cycles.py export /tmp/rc01-turn2 --cycle RC01 --turn 2 --history /tmp/rc01-after1.json
python3 backend-devops-theory/assets/review-benchmark/review_cycles.py export /tmp/rc01-turn3 --cycle RC01 --turn 3 --history /tmp/rc01-after2.json
```

После каждого export сначала получить и сохранить ответ, и только затем выдать следующий ход. Сценарий продолжает тот же преподаватель с доступом к уже выданным материалам. Новый каталог обязателен: экспорт не перезаписывает старую выдачу. Следующий ход требует ровно предыдущие ходы, правильную версию/сценарий и заполненный ответ; ошибочное ревью сохраняется и не блокирует выдачу следующей сдачи. Это позволяет наблюдать последствия ошибки без подсказки от оценщика.

Аналогично провести RC02 и RC03. Подготовка комплекта и автоматические тестовые JSON не являются реальным диалогом преподавателя с учеником.

## Проверить запись и переходы

```sh
python3 backend-devops-theory/assets/review-benchmark/review_cycles.py check /tmp/rc01-after3.json
python3 backend-devops-theory/assets/review-benchmark/review_cycles.py score /tmp/rc01-after3.json
```

`check` проверяет последовательность, исходные сообщения и хеши, заполненность ответов/снимков и формат состояний. Каждый ход содержит хеш предыдущей записи: случайная правка прошлого ответа или снимка обнаруживается. Это проверка согласованности записей, не доказательство их происхождения и не цифровая подпись.

`score` дополнительно проверяет:

- Статус каждого исходного критерия и итог приёмки на всех трёх шагах.
- Сохранение ID прежних замечаний, их связи с критерием и истории снятия.
- Частичное исправление с сохранением открытого дефекта.
- Новую регрессию в ранее выполненном критерии.
- Снятие ложного замечания как `withdrawn`, отдельно от исправления кода как `closed`.
- Приёмку полного исправления без новых требований.

Метрики: `matched_turns`, `premature_acceptances`, `missed_regressions`, `lost_issue_ids`; по каждому ходу — различия критериев, итога, состояний замечаний и ID. Пропущенный финальный ход не превращается в успешный цикл. `structured_cycle_matches` означает только совпадение записанных состояний и меток с данным сценарием.

Коды выхода: 0 — соответствующая проверка пройдена / выдача или шаблон созданы; 1 — неполный transcript или несовпадение состояний; 2 — неверный вход/ошибка чтения. Для score код 0 не является подтверждением педагогического качества.

## Оценить объяснения и поведение преподавателя

```sh
python3 backend-devops-theory/assets/review-benchmark/review_cycles.py assessment-template /tmp/rc01-after3.json > /tmp/rc01-assessment.json
python3 backend-devops-theory/assets/review-benchmark/review_cycles.py score /tmp/rc01-after3.json --assessment /tmp/rc01-assessment.json
```

Между этими командами оценщик заполняет файл по [четырём шкалам](ASSESSMENT.md). Каждому ходу соответствует отдельная строка RC01:01, RC01:02, RC01:03. Оценка связана с полным transcript, включая исходные хеши, ответы и снимки; изменение содержимого требует новой оценки. Непроверенные ходы остаются pending.

Дополнительно к общей рубрике проверить весь цикл:

| Свойство | Достаточное основание в ответе и состоянии |
| --- | --- |
| Частичное исправление | Преподаватель объяснил, что именно закрыто, что ещё не выполнено и каким действием проверить остаток |
| Регрессия | Повторно рассмотрен затронутый прежний критерий; новый дефект не скрыл исправление старого |
| Обоснованное возражение | Преподаватель прямо пересмотрел собственный вывод по v1, назвал прежнее требование ошибочным, снял замечание без вымышленного изменения кода |
| Завершение | Все объявленные критерии подтверждены, история сохранена, следующий шаг соответствует приёмке именно этой практики |
| Согласованность | Дословный ответ, review, PROGRESS.md и NOTES.md не противоречат друг другу; заявленные проверки действительно выполнены или названы анализом кода |

Не оценивать признание ошибки по наличию слова «извиняюсь». Важны пересмотр основания и исправленное решение о приёмке. Не считать совпадение JSON-статусов доказательством, что текст помог ученику. Автоматический отчёт сохраняет `semantic_assessment_required=true` и `explanation_verified=false`; заполненные внешние оценки фиксируют суждение названного оценщика, а не измеренный учебный эффект.
