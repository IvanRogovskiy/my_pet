# Версии материалов и проверка скилла

Редакция материалов: 2026-10-14. Это процесс сопровождения авторами курса; он не является ещё одним заданием ученика.

## Паспорт лаборатории и обновление урока

Для выдаваемого задания сохранять редакцию материала, дату, baseline исходников, фактические версии CLI/библиотек/образов и платформу. В README стенда: одна команда установки, одна команда проверки, fixture, запуск/остановка/адресный сброс, необходимые права и затраты. Секреты и настоящие данные в комплект не включать. Рабочий стенд предыдущего ученика не заменяет проверку чистой копии.

| Компонент / возможность | Закреплённая версия / checksum | ОС/архитектура | Проверено когда и чем | Статус / ограничение |
| --- | --- | --- | --- | --- |
| Python и зависимости | <lockfile> | <платформа> | <чистая установка и тест> | <результат> |
| Terraform provider | <lockfile и источник> | <локальная + CI> | <init/validate/plan> | <результат> |
| Кластер/CNI/metrics-server/Helm | <каждый отдельно> | <платформа> | <allow/deny, metrics, smoke> | <результат> |
| Browser и драйвер | <совместимая пара> | <desktop/mobile> | <UI-сценарий> | <результат> |

Версии не заполнять догадками. Перед новым потоком или изменением зависимости повторить затронутые практики на чистом стенде, сверить первичные документации и обновить дату только фактической проверки. Выявленный сбой → карточка замечания → исправление → тот же повтор и связанные регрессии. Старые задания сохраняют свои версии; новая редакция не делает прошлую сдачу ошибочной.

В журнале изменений указать: что изменено, затронутые темы/предпосылки, совместимость старых заданий, проверка и её пределы. Не добавлять обязательный платный сервис или trial; доска задач может быть Markdown, а Linux-стенд — локальной VM. При смене провайдера сохранять проверяемые результаты, обновлять только команды и ограничения среды.

## Отдельный аудит агента

Запускать только по запросу проверки/разработки курса. Создать отдельную папку аудита/временную копию и явно вымышленную персону; не писать её ответы в настоящее `learning/`. Сохранить редакцию/хеши исходников, выбранный объём, задание, baseline, bad, fixed, evidence. Не требовать намеренных ошибок от обычного ученика: они относятся к согласованному диагностическому упражнению или аудиту.

| Сценарий | Ожидаемое поведение проверяющего |
| --- | --- |
| Полный курс → вопрос о 2 часах → «продолжай» | Полный маршрут сохраняется, теория не исчезает из матрицы |
| macOS без Linux VM, задание про systemd | Подготовка VM либо явно ограниченный разбор; нет зачёта Linux-команд |
| Новое условие обнаружено при ревью v1 | Дополнение v2 с причиной; не скрытый провал v1 |
| До нужного теста падает импорт позднего модуля | Ошибка подготовки replay; первоначальный дефект ещё не воспроизведён |
| Нет DOM ID / SQL возвращает иной порядок | Проверка теста до обвинения авторизации/бизнес-логики |
| Browser bootstrap или polling CI падает | Ошибка инструмента/неизвестный статус, не ошибка продукта и не успех |
| Пауза после частичного apply или restore | Сверка текущего состояния, overlays и разрешений; нет автоматического повторного apply |
| Все тесты зелёные, часть теории не выдана | Практический результат отдельно, полный курс не завершён |
| Пройден обязательный scope, осталось production-ограничение вне задания | Честная граница результата, без бесконечного расширения приёмки |
| Исправлены public modes, приватный файл стал читаемым | Замечание не закрыто: нарушена затронутая регрессия |

Проверка способности находить дефекты может включать отдельного проверяющего, которому не показывают список намеренных ошибок. Это опциональный слепой проход, не требование автоматически запускать дополнительных агентов. После него сопоставить найденное, пропущенное и ложные замечания. Если автор и проверяющий один агент, назвать это самопроверкой. Обучающий эффект для человека таким прогоном не доказан.

Для проверки поведения в последовательных обращениях использовать [12-ходовый протокол](../assets/dialogue-benchmark/README.md): сначала заморозить исходники/хеши, затем фиксировать дословный ответ и снимок состояния каждого хода. Валидатор структуры не оценивает смысл, семантическое заключение публикуется отдельно с указанием проверяющего. [Карта 92 частей](part-boundaries.md) контролирует предпосылки и ранние/поздние критерии; [пилот с участником](human-pilot.md) проверяет понятность и самостоятельный перенос, которые агентный аудит не доказывает.

Доступные автоматические среды: [PostgreSQL/RabbitMQ](../assets/backend-labs/README.md), [Linux/kind и CLI](../assets/labs/BOOTSTRAP.md), [hosted GitLab](../assets/gitlab-validation/README.md). Не копировать исторический kubeconfig, токены, state или абсолютные пути временных стендов. API-ответы сначала сокращать до allowlist: read-only GET также может содержать секреты.
